# ESP-NOW 双角色通信

需要两块兼容的 ESP32-C3 板，一块烧录 `receiver`，另一块烧录 `device`。两端都使用 STA 模式、信道 1；业务单播设置了共享 PMK/LMK。配对请求/接受使用广播，不加密。

## 密钥

`hello_world/main/wireless_config.h` 提供公开的 16 字节演示密钥。它们不是秘密，也不与原测试板使用的配置相同；需要在两端使用同一套构建配置。密钥编译进二进制，勿把含私人密钥的固件作为公共附件分发。

自主实验时可以在本地将两个宏替换为各 16 字节的私有值，并在两块板上同时重建、烧录。此文件会被 Git 跟踪，提交前须恢复演示值。本项目尚未实现每设备密钥配置、认证配对或完善的防重放机制；加密单播不能代替完整的安全设计。

## 配对

1. 接收端接 USB，打开 115200 波特率的串口终端。
2. 长按接收端 GPIO3 约 3 秒，出现 `PAIRING window=60s`。
3. 未配对设备上电后会在 60 秒内广播配对请求；已配对设备要换接收端，也长按设备端按键约 3 秒。
4. 接收端出现 `PAIRING candidate found`，随后 `READY device=paired`。
5. 配对 MAC 写入 NVS，普通重启会尝试恢复。更新密钥时必须同时更新两端；需要重新配对时使用上述长按流程。

请在一次只准备一对设备的环境操作，避免同时打开多组配对窗口。

## 命令

接收端支持回显和退格，以回车或 LF 提交。`HELP` 在接收端处理，其余命令转发到设备端。

| 命令 | 回复示例 |
| --- | --- |
| HELP | 列出支持命令 |
| ADC? | ADC raw=… adc_mv=… battery_mv=… |
| LED 1 / LED 0 | OK LED 1 / OK LED 0 |
| LED TOGGLE | OK LED 0 或 OK LED 1 |
| INFO? | INFO fw=espnow-v1 mac=… up=… heap=… |

未配对、等待上一条命令或重试失败时可能出现 `ERROR RADIO_OFFLINE`、`ERROR BUSY` 或超时提示。不要同时给多个命令依赖固定执行顺序。

设备端实现按键按下事件、有限重试、序号和最近一次响应缓存；释放事件与 standalone 行为不同，不应假定无线端同样输出 `BUTTON 0`。该缓存不构成跨重启的去重或防重放保证。

历史终端日志见 [2026-07-31 记录](evidence/espnow-terminal-2026-07-31.txt)。其中低电压数值只能证明 ADC 命令产生回复，不能据此确认电池测量准确；公开演示密钥版本尚未重新进行双板验收。
